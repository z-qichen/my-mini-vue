## 二、HistoryManager 核心机制图（指针栈模型）

这是最关键的数据结构，用**指针栈**来实现撤销/重做：

### 初始状态：空栈
```
┌────────────────────────────────────────┐
│  history = []                          │
│  pointer = -1                          │
│  canUndo = false    canRedo = false    │
└────────────────────────────────────────┘
```

### 执行 Command1（如：添加标题组件）
```
┌────────────────────────────────────────┐
│  history = [Command1]                  │
│  pointer = 0 ───────────────► [✅]     │
│  canUndo = true     canRedo = false    │
└────────────────────────────────────────┘
```

### 执行 Command2（如：修改文字颜色）
```
┌────────────────────────────────────────┐
│  history = [Command1, Command2]        │
│  pointer = 1 ─────────────────► [✅]   │
│  canUndo = true     canRedo = false    │
└────────────────────────────────────────┘
```

### 执行 undo() 撤销
```
┌────────────────────────────────────────┐
│  history = [Command1, Command2]        │
│  pointer = 0 ───────────────► [✅]     │
│  调用 Command2.undo() 恢复颜色          │
│  canUndo = true     canRedo = true     │
└────────────────────────────────────────┘
```

### 执行 undo() 再撤销
```
┌────────────────────────────────────────┐
│  history = [Command1, Command2]        │
│  pointer = -1                          │
│  调用 Command1.undo() 删除标题组件      │
│  canUndo = false    canRedo = true     │
└────────────────────────────────────────┘
```

### 执行 redo() 重做
```
┌────────────────────────────────────────┐
│  history = [Command1, Command2]        │
│  pointer = 0 ───────────────► [✅]     │
│  调用 Command1.execute() 重新添加标题   │
│  canUndo = true     canRedo = true     │
└────────────────────────────────────────┘
```

## 三、分支场景：中间状态执行新命令

当你在撤销到中间某步后，执行了新操作，**后面的历史会被截断**：

```
当前状态：已执行 Command1、Command2、Command3
┌────────────────────────────────────────┐
│  history = [C1, C2, C3]               │
│  pointer = 2 ─────────────────► [✅]   │
└────────────────────────────────────────┘
              │
              ▼ undo() 两次
┌────────────────────────────────────────┐
│  history = [C1, C2, C3]               │
│  pointer = 0 ───────────────► [✅]     │
│  （C2、C3 还在栈里，但 redo 才能到）    │
└────────────────────────────────────────┘
              │
              ▼ 此时执行新命令 Command4
┌────────────────────────────────────────┐
│  history = [C1, C4]  ◄── C2、C3 被截断丢弃！│
│  pointer = 1 ─────────────────► [✅]   │
└────────────────────────────────────────┘
```

对应代码（`history.ts` 第36-38行）：
```typescript
if (this.pointer < this.history.length - 1) {
  this.history = this.history.slice(0, this.pointer + 1)
}
```

## 四、防抖合并机制图（DebounceMerger）

用于解决**连续快速输入**（如打字、拖拽滑块）产生大量历史记录的问题：

### 不合并的情况（灾难）
```
用户连续输入 "Hello"（5个字母，快速输入）

┌────────────────────────────────────────────┐
│  历史栈: [输H, 输e, 输l, 输l, 输o]          │
│  撤销5次才能回到空文本                       │
│  体验极差！                                  │
└────────────────────────────────────────────┘
```

### 使用 DebounceMerger 合并后
```
┌────────────────────────────────────────────┐
│  历史栈: [输H, 输"ello"]  ← 合并为2条       │
│  或更理想: [输"Hello"]   ← 合并为1条        │
│  只需撤销1次就回到空文本                     │
│  体验流畅！                                  │
└────────────────────────────────────────────┘
```

### 合并判断逻辑

```
updateStatus("title", "H")  ──► mergeKey = "update-0-title"
         │                              │
         ▼                              ▼
   DebounceMerger.tryMerge() ◄── lastMergeKey = null
         │
         └── 不同 ──► shouldMerge = false
                    └── 记录 pendingOldValue = ""
                    └── 压栈执行
                    └── 启动 300ms 定时器

updateStatus("title", "He") ──► mergeKey = "update-0-title"
         │                              │
         ▼                              ▼
   DebounceMerger.tryMerge() ◄── lastMergeKey = "update-0-title"
         │
         └── 相同 ──► shouldMerge = true
                    └── 重置定时器
                    └── 不压新栈，而是 replaceCurrent()
                    └── 新命令的 oldValue 用 pendingOldValue
```

对应代码（`useEditor.ts` 第319-341行）

## 五、命令对象结构图

每个命令都是一个符合 **Command 接口** 的对象：

```
┌─────────────────────────────────────────────────────────┐
│                    Command 接口                          │
├─────────────────────────────────────────────────────────┤
│  type: 'add' | 'remove' | 'update' | 'move'            │
│  execute: () => void    ◄── 执行操作（redo 也会调用）    │
│  undo: () => void       ◄── 撤销操作                    │
│  mergeKey?: string      ◄── 可选，用于防抖合并的标识      │
└─────────────────────────────────────────────────────────┘
```

### 示例：createUpdateCommand 生成的命令
```
┌─────────────────────────────────────────────────────────┐
│  {                                                      │
│    type: 'update',                                      │
│    mergeKey: 'update-0-title',  ◄── "第0个组件的title"   │
│    execute: () => {                                     │
│      coms[0].status.title.status = '新标题'              │
│    },                                                   │
│    undo: () => {                                        │
│      coms[0].status.title.status = '旧标题'              │
│    }                                                    │
│  }                                                      │
└─────────────────────────────────────────────────────────┘
```

## 七、核心设计模式总结

| 设计模式 | 应用位置 | 作用 |
|---------|---------|------|
| **命令模式 (Command)** | `commands.ts` | 将操作封装为对象，支持 execute/undo |
| **备忘录模式 (Memento)** | `createRemoveCommand` 中的 `deepCloneStatus` | 保存操作前的状态快照 |
| **职责链/栈结构** | `HistoryManager` | 用指针栈管理命令序列 |
| **防抖 (Debounce)** | `DebounceMerger` | 合并连续操作，优化撤销体验 |

| 文件 | 职责 |
|-----|------|
| `src/stores/history.ts` | 定义 `Command` 接口、`HistoryManager` 指针栈、`DebounceMerger` 防抖器 |

## 九、设计精髓

这个设计的精髓在于：**命令模式解耦了"做什么"和"怎么做"**，`HistoryManager` 只关心命令的入栈/出栈/指针移动，完全不关心具体业务逻辑；而具体的添加/删除/修改逻辑都封装在各个 `createXxxCommand` 工厂函数里。这样既保证了撤销重做的通用性，又保留了业务灵活性。
